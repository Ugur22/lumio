# Architecture

```
Browser (React + Tailwind, built by Vite)
   │  JSON + server-sent events
   ▼
FastAPI (server.py → app/ routes, models.py)
   ├── SQLite                chats, accounts, sessions, invites
   ├── Chat images           <data dir>/images/<chat id>/
   ├── Provider profiles     profiles.json locally; one file per account on a server (no keys)
   ├── API keys              OS keychain locally; encrypted secrets file on a server
   └── outbound calls ──►  your LLM provider, Tavily (optional), pasted web links
```

- **Frontend** (`frontend/`): React 19, TypeScript, Tailwind, TanStack Query and Zustand. Markdown goes through a sanitizing pipeline, and code blocks run in a sandboxed iframe. API types in `frontend/src/api.gen.ts` are generated from the backend (`make types`).
- **Backend**: `server.py` assembles the FastAPI app from `app/` (chat, profile and auth routes, prompt building in `story.py`, streaming in `streaming.py`, provider access in `providers.py`). It streams replies to the browser as SSE and serves `frontend/dist` when it exists.
- **Persistence**: SQLite in WAL mode. A reply takes a short per-chat lease, so a second send to a busy chat gets `409`.
- **Providers**: the backend calls the provider's base URL directly. The browser never talks to a provider and never sees a key.

## Modes

Setting `DOLPHINLLM_PUBLIC_HOST` makes the app a deployed instance; without it, it is local.

- **Local:** no sign-in. State-changing profile and key routes accept only a browser origin that is the local server.
- **Deployed:** invite-only accounts with argon2-hashed passwords and 30-day session cookies. Every chat, profile and key belongs to one account, and another account's data answers 404. State-changing requests must carry a matching `Origin`. Five failed sign-ins lock a username for 15 minutes. The interactive API docs are off. uvicorn must listen on 127.0.0.1 behind the proxy, because the client address for rate limiting comes from it.

The app refuses to start with a server-only setting (`DOLPHINLLM_SECRETS_FILE`, `DOLPHINLLM_SECRET_KEY`, `DOLPHINLLM_SECRET_KEY_FILE` or `DOLPHINLLM_ADMIN_USER`) but no `DOLPHINLLM_PUBLIC_HOST`, because it would otherwise treat every visitor as the local user.

## Data and privacy

**Stored on the machine running Lumio:**

| What | Local | Deployed (paths from `deploy/lumio.service`) |
| --- | --- | --- |
| Chats, bible, lore, summaries, per-chat settings | `data/chats/lumio.db` (`DOLPHINLLM_DB_FILE` overrides; `DOLPHINLLM_DATA_DIR` moves the directory) | `/var/lib/lumio/lumio.db` |
| Accounts, sessions, invites | not used | same database (hashes only for passwords, session tokens and invite codes) |
| Attached and generated images | `data/chats/images/` | `/var/lib/lumio/chats/images/` |
| Song transcripts (original and your edits), local only; see [transcription.md](transcription.md) | same database | not offered |
| Provider profiles (name, URL, model, flags) | `profiles.json` | `/var/lib/lumio/profiles/<account id>.json` |
| Provider and Tavily API keys | OS keychain | `/var/lib/lumio/secrets.json`, encrypted with the master key |
| Logs | `logs/app.jsonl` | `/var/lib/lumio/logs/app.jsonl` |

Images are deleted after 30 days (`DOLPHINLLM_IMAGE_RETENTION_DAYS`) or with their chat; older messages show a placeholder and the model is told the image is gone. Logs hold metadata only: keys and message and summary bodies are redacted by field name. Chats are plain text in the database and are not encrypted by Lumio.

**Sent to external services, only when the matching feature is used:**

| To | What |
| --- | --- |
| Your LLM provider | The system prompt and formatting notes, chat instructions, story bible, triggered lore, summary, all messages not covered by the summary, your new message, attached images (vision profiles) and fetched web text. Summaries are generated by sending older messages to the same provider. With Web on, a short query-rewrite call also sends your latest message and the last few messages, each cut to 300 characters |
| Your provider's image endpoint | The prompt for each illustration |
| Your LLM provider, when you attach a transcript to a message | The transcript text (your edited version if you edited it). Transcription itself runs locally; yt-dlp fetches the audio from YouTube |
| Tavily (`api.tavily.com`) | The search query, only when Web is on and a key is saved |
| Web pages you link | A plain GET from the server, public addresses only |

A key is sent to the profile's base URL and nowhere else. What providers retain is governed by their own terms, which Lumio does not control.
